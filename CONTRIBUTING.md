# Contributing

## Before you contribute

Contributions must support authorized, defensive assessment work. Do not add malware, exploitation, persistence, credential access, endpoint-protection evasion, invasive monitoring, or content that instructs others to bypass security controls.

Use fictional, synthetic, or thoroughly redacted fixtures. Never include client names, usernames, hostnames, IP addresses, serial numbers, raw endpoint logs, forensic images, tokens, passwords, keys, or other personal or sensitive data.

## Change expectations

1. State the purpose, authorization assumptions, data sensitivity, and collection limits in the relevant documentation.
2. Keep collection examples non-destructive, read-only where possible, and narrowly scoped.
3. Describe observations and limitations accurately. Do not claim compromise detection, attribution, or compliance unless the evidence and approved scope support that claim.
4. Update linked documentation and validate Markdown links before requesting review.
5. Keep pull requests focused and explain any changes to privacy, retention, or evidence handling.

## Review standard

Maintainers review changes for safety, factual accuracy, minimization, clarity, licensing, and fit with the portfolio scope. A contribution may be declined when authorization, privacy impact, or defensive value is unclear.
